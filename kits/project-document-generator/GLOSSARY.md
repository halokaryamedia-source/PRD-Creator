# Glossary

| Term | Definition |
|---|---|
| Source | Original/current project material preserved as evidence before being used as authority. |
| Golden Sample | Approved reference for the minimum document function and quality expected from this PRD family. It does not define project facts and is not the active project template. |
| Clarification | Wording/explanation improvement that preserves existing meaning. |
| Completion | Missing documentation recovered from strong evidence/necessary implication without choosing a new material design option. |
| Proposal | Material product/design choice suggested for approval; it is not project truth until explicitly approved. |
| Blocked | Material required scope that cannot be resolved responsibly from current evidence/authority. |
| Source Inventory | Persistent source identity, provenance, role, status, and inspection coverage needed for resumability. |
| Requirement Register | Persistent material production requirements, exclusions, conflicts, recovery, and approval exceptions. |
| Intake State | Single resumable Flow 2 status plus one practical next step. |
| Review | Conditional user-facing summary of material decisions/concerns when Flow 2 needs input. |
| Canonical Content | `work/content.md`; source of truth for PRD meaning. |
| Gameplay Package | One gameplay unit represented by Gameplay Overview, Level Design, and Developer production surfaces. |
| Render Projection | `work/render-data.json`; compact derived structure required to render the current canonical PRD. It is not semantic authority. |
| Approved PRD Template | `template/approved-document.html`; generic presentation/runtime infrastructure used to render PRD content. It contains no project facts. |
| Rendering | Deterministically projecting current canonical PRD meaning into the approved generic template without inventing or changing project facts. |
