# Glossary

| Term | Definition |
|---|---|
| Source | Current project material used as evidence. A file source may be retained in the repository or externally when duplicating it adds no production value; `state/source-inventory.yaml` records its identity, role, inspection boundary, and retention/provenance needed for continuity. |
| Golden Sample | The approved **canonical visible page prototype** for this gameplay PRD family. It locks page family, visible structure, labels, component order, reading pattern, and presentation behavior; it never supplies another project's facts. |
| Clarification | Wording/explanation improvement that preserves existing meaning. |
| Completion | Missing documentation recovered from strong evidence or a necessary implication without selecting a new material product/design option. |
| Proposal | A concrete material product/design/development choice suggested by the AI when authority does not settle the answer. It remains pending until the user approves or corrects the relevant Simple Chat Preview. |
| Blocked | Material required scope for which no responsible proposal can be formed from current authority and constraints. |
| Source Inventory | Persistent source identity, provenance, role, status, inspection coverage, and retention information needed for resumability. |
| Requirement Register | Persistent material production requirements, exclusions, conflicts, recovered implications, proposals, and approval exceptions. |
| Intake State | Compact resumable Flow 2 status. Positive readiness and preview approval are explicit; a stale downstream `next_step` is not required after another Flow owns continuation. |
| Simple Chat Preview | The Flow 2 user checkpoint for reviewing the complete proposed project model before Flow 3. It is chat output, not another project artifact. |
| Review | Conditional user-facing decision/recovery summary used only when it materially helps; it is not a mandatory Flow artifact. |
| Canonical Content | `work/content.md`; source of truth for accepted PRD meaning. |
| Gameplay Package | One gameplay unit represented by Gameplay Overview, Level Design, and Developer production surfaces. |
| Render Projection | `work/render-data.json`; compact derived structure needed by the deterministic renderer. It is not semantic authority. |
| Approved PRD Template | `template/approved-document.html`; the runtime template path. Its bytes must remain identical to `template/golden-sample.html`, the canonical Golden reference artifact. It is not a generic redesign surface. |
| Rendering | Deterministically projecting current canonical PRD meaning into the exact approved Golden prototype without inventing or changing project facts. |
| Semantic Readiness | The single persisted Flow 4 result for the integrated New Reader, Level Designer, Developer, Content Purity, Project Consistency, and Golden Placement lenses. |
| Material Conservation | Separate Flow 4 proof that independently actionable approved rules were not lost during Humanize/projection/rendering. |
| Visual Sanity | Browser/rendered evidence that the relevant pages are readable and free of concrete layout defects. Static HTML inspection alone cannot claim this PASS. |
