## Test result

The reverse/forward method worked as intended but exposed a more important upstream problem: the authoritative Clockwork file contains material contradictions between its own page families.

Representative conflicts found:

1. **Resonance Engine** — Gameplay material reveals the first target after about 90 seconds of free play and uses sequential targets, while Developer Requirements say to show the target from the start; another flow description reads as a single-target challenge.
2. **Broken Gallery** — Gameplay Flow describes checkpoint/phased route behavior and late collapse/recovery, while package production pages describe three equal routes with a deterministic collapse around 60% and alternative-route switching.
3. **Warden Halls** — Gameplay Flow limits Echo Pebble disabling to wall/floor traps and says ceiling traps cannot be disabled, while production surfaces describe safe remote testing on every trap.
4. **Gremlin’s Workshop** — Gameplay Flow explicitly says the final challenge is not a reversed-pipe rule and instead removes one known connection permanently, while Level/Developer surfaces use a global Elbow-rule inversion.
5. **Vault Restored** — player/story surfaces name the cosmetic reward `Clockwork Wayfinder`, while Developer requirements contain `Vault Explorer Banner`.

These are product/mechanic conflicts, not formatting differences. Selecting one side during generation would invent authority, so a full regenerated Clockwork PRD was intentionally **not** produced.

## Correction made from the test

The first wrong owner is Flow 2 source intake, not the renderer.

`SOURCE-INTAKE.md` now explicitly requires a bounded cross-surface consistency sweep for mature/structured PRD sources before `ready_for_prd`:

```text
Gameplay Flow
↔ Gameplay Overview
↔ Level Design
↔ Developer
```

Only repeated high-impact claims are compared: progression/counts, trigger/timing, mechanic/state change, fail/recovery, scoring/result, reward/handoff, interruption/reset, and other behavior that could make production roles implement different games.

A single authoritative file is no longer assumed internally consistent. Same-authority material conflicts that cannot be resolved by stronger approved authority must remain `needs_decision` / `blocked`. No new schema, similarity score, coverage artifact, renderer layer, or source-specific automated fixture was added.
