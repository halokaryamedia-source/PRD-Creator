## Flow 2 recovery + problem-solving contract

```text
source inventory + inspection
→ explicit facts/rules/exclusions
→ topology + terminology
→ cross-role implications
→ production coverage
→ lifecycle + quantitative + operational clarity
→ global/local coherence + known-constraint feasibility
→ problem framing
→ Resolution Ladder
→ impact propagation
→ humanized grouped decision package only if needed
→ ready_for_prd
```

Key rules:

- material user instructions are persisted as source authority even when no file exists;
- source inspection coverage can be recorded as targeted/full for resumability;
- source-level supersession applies only when the whole source is replaced;
- removals/exclusions are first-class requirements;
- topology includes package order, global ownership, dependencies/transitions, and final result when relevant;
- material mechanics are checked for necessary Gameplay / Level Design / Developer / result-reset implications;
- lifecycle scan checks applicable precondition/trigger/active/success/fail/result/reset behavior without forcing irrelevant stages;
- directly related duration/count/capacity/scoring facts are checked for contradiction before drafting;
- materially vague wording is resolved only when it would create different production behavior; qualitative direction is not forced into fake metrics;
- shared/global defaults and local exceptions must be explicit and coherent;
- authoritative known project/platform constraints are checked without turning generic best practice into authority;
- each material issue is framed around observed problem, consequence, constraints, intended outcome, and affected roles;
- solve-before-ask ladder is authority → safe Completion → supported recommendation → balanced tradeoff → Blocked/direct decision;
- `Recommended` is used only when evidence/goals/constraints genuinely favor one option;
- one approved/recovered resolution is propagated to all actually affected requirements;
- related issues are grouped only when one root decision genuinely resolves them;
- optional advisory ideas stay out of the user's way by default;
- missing optional/irrelevant detail stays open/neutral rather than becoming filler or a user question;
- once `ready_for_prd` is reached, Flow 2 stops rather than continuing speculative design optimization.
