# Product Boundaries

Status: active policy

## Project Document Generator Owns

- reading and understanding project source;
- identifying missing, unclear, conflicting, or under-specified documentation;
- distinguishing clarification/completion from actual design decisions;
- completing supported gaps under its approval rules;
- producing canonical project content;
- rendering the approved project document through the fixed approved template;
- preparing documentation usable by developers, level designers, and production stakeholders.

## Project Document Generator Does Not Own

- silently changing project design;
- treating its own proposal as approved;
- changing the approved presentation system without explicit scope;
- producing voice performance text as a substitute for project documentation.

## Voice Production Kit Owns

- consuming sufficiently mature gameplay/story/project documentation;
- locating justified voice moments;
- grouping Main Story and Radio Communication by gameplay/project section;
- writing natural performance-ready text for ElevenLabs;
- preserving official project terminology and sequence;
- producing the required Voice Production deliverable.

## Voice Production Kit Does Not Own

- repairing unresolved PRD design decisions by invention;
- creating new gameplay mechanics, lore, triggers, scoring, rewards, or objectives merely to support a voice line;
- becoming a second project-document generator.

## Shared Boundary Rule

If voice production discovers that a required story/gameplay fact is genuinely missing and cannot be recovered safely, the issue routes upstream to project documentation rather than being invented downstream.
